# Changelog

All notable changes to this project are documented in this file.

Maintain this file as part of product or release-affecting work. Release automation publishes the version declared in `package.json`.

## 1.8.3 - 2026-11-27

### Changed

- `concept-asset-builder` learns from its first building (a two-storey shop, reviewer 6.99 → 7.92):
  - `wear_stats.py` measures wear that is darker than the surface (chip `mode: "dark"`, peeling plaster over
    a darker layer) against a high-percentile wall reference in a wide window, and drops per-view
    `exclude_rects` (shop glazing, signs) from every measurement.
  - New `overlay_masks.py` draws the chip, rust and grime masks over the concept or a render in one command.
  - `codex_review.sh` attaches the builder's extra renders (`out/<pipeline>/extra_*.png`: interior cutaways,
    sections, close-ups) so parts the five views cannot show are reviewed too.
  - The Blender, Three.js and Godot studios fit the object on both image axes, so wide objects stay in frame.
  - `measure_silhouette.py` reports positions in object coordinates per view (the back mirrors x, the
    sides report z).
  - SKILL.md adds a `constraints` block for the owner's hard numbers, a check of generated sheets for
    stamped wear patterns, a section on large and composite objects (plans, extras, instancing, expected
    time and scores) and the saturation caveat of coverage measurements; field lessons and the builder
    brief template follow.

## 1.8.2 - 2026-11-26

### Added

- Added the standalone `concept-asset-builder` skill: builds one game object from its concept sheet to
  concept fidelity in Blender and/or Three.js, in the shared style of its scene. A spec measured from the
  concept's pixels (`measure_silhouette.py`), a numeric wear description per zone, part and side backed by
  calibrated, scale-normalised wear measurements (`wear_stats.py`), builder agents in a frozen shared studio,
  and an independent reviewer of another model (`codex_review.sh`, Codex CLI, with a subagent fallback)
  that scores a weighted rubric, sees its previous review and the builder's decisions log. An owner
  checkpoint on the scene's pilot object feeds a scene style file used by every later object. Ships
  `init_workspace.sh`, Blender/Three.js/Godot studio templates, baked GLB export with per-part baking,
  texture generation (`gen_texture.sh`), templates (builder brief, rubric, zones, wear description, scene
  style), the shared wear language, field lessons from real runs and example wear implementations, with
  model-free tests that skip without Pillow, numpy or scipy.

### Changed

- `concept-scene-builder` gains the object conveyor: a `build: asset` kit type built with
  `concept-asset-builder`, recursive decomposition of large objects into parts with an `assembly` block,
  a pilot object approved by the owner whose remarks become the scene style file, the remaining objects
  in parallel, and assembly plus the look pass only after the objects pass their reviews.

## 1.8.1 - 2026-11-16

### Added

- Added the standalone `art-direction-pass` skill: an iterative art direction pass that brings an
  existing game's visuals closer to its concept art (deterministic preset captures, per-category
  direction documents, a gap report, one-group-at-a-time iterations kept or reverted on a blind A/B
  reviewer's verdict) and codifies the result as a graphics profile, material presets and asset
  checklists. Ships a Godot 4 capture autoload and preset template, `compare.py` (comparison sheets,
  per-preset blind pairs whose mapping is never written inside the reviewer's folder) and
  `metrics.py` (luminance, saturation, palette), with model-free tests that skip without Pillow and
  numpy. The capture autoload records GPU and CPU render time per preset with vsync off.
- Added the standalone `concept-scene-builder` skill: rebuilds a concept image as a game environment
  (terrain, water, roads, vegetation, buildings, lighting; no units) from a parametric, data-driven
  asset kit and layout JSON for grid or free-form scenes, with a golden scene as the comparison
  fixture, a per-asset defect pass and field lessons from real runs. Ships `grid_overlay.py`
  (homography grid or metre measurement grid over the concept), `crop.py` and `blend.py` with
  model-free tests; works alongside `art-direction-pass` and falls back without it.
- Added the standalone `machine-builder` skill: spec-driven, rigged hard-surface machines (walkers,
  tracked, wheeled, hover, rotorcraft, fixed-wing, static) generated by Blender kit scripts, with an
  example spec and `validate.py`, which checks per-pose part collisions, support margin, budgets,
  islands and sockets (with base poses for sweeps, translations such as suspension travel and
  per-pose ground checks) and exits non-zero on any failure or error, never leaving a stale passing
  report (covered by a Blender test that runs when Blender is available).

### Changed

- Version parts are now named `release.major.minor`, effective from 1.8.1: `minor` (last digit) for
  fixes and backward-compatible collection content such as new skills, `major` for new or changed
  consumer-facing CLI commands and adoption workflows, `release` for breaking changes; the highest
  bump in a release wins.

## 1.8.0 - 2026-11-04

### Added

- Added the standalone `roadmap` skill: one self-contained Gantt page per project, built from the
  TaskPilot items, the git history of those files and of commits naming item ids, and an optional plan
  file (phases, estimates, milestones). `scripts/roadmap.py` provides `init`, `build`, `check` and
  `path` (standard library only, deterministic output); every project uses the same `en`/`ru`
  template, stamped into the page as `<meta name="roadmap-template">` with the data as JSON, so a
  consumer can read it and `check --template-from` detects template drift. Includes a post-commit
  hook, the format reference and model-free tests.

## 1.7.0 - 2026-10-21

### Added

- Added the standalone `kimodo-motion` skill: local NVIDIA Kimodo text-to-motion through kimodo.cpp
  with a shipped key-pose patch (`kmd-generate --constraints` reading upstream's `fullbody`,
  `end-effector` and hand/foot constraints), start/end key poses held over several frames with hand
  and foot orientation, key-pose error gates, offset easing of the model's residual, frame sheets
  with per-frame junction strips, and Blender scripts for rig pose -> key pose and rig retargeting
  with a direction gate. Includes model-free tests and a Blender round trip.
- Added the standalone `self-reflection` skill with incremental Codex session review,
  persistent checkpoints, evidence-backed recommendations and an offline HTML history.
  Includes Python helpers/tests, JSON and HTML templates, and a Claude Code exporter that
  works from CLI-installed copies. Both Claude and Codex installations read Codex JSONL;
  native Claude transcript parsing is not included.
- Added the standalone `astro-preview` skill for local browser previews of project images,
  audio, models and animation. It covers a consumer-configured checkout, idempotent project
  roots, stable links/CLI open, linked animation inspection, HTML/Vite profiles, audio A/B RMS,
  pixel differences, real browser verification and explicit runtime/write boundaries.

## 1.6.0 - 2026-10-10

### Added

- Added a low-poly geometry policy, parametric organic-form guidance, generated/imported
  mesh provenance and licence checks, and hash manifests for frozen deliveries.
- `mesh_report.py --organic` persists component and self-overlap counts and gates mesh
  health, single-component geometry and zero self-overlap. Explicit `--strict --pairs A:B,C:D`
  checks world-space surface intersections. Legacy `--strict` remains compatible.

### Changed

- `blender-3d` skills carry practices learned in a consumer game project: a measured spec
  sized to the task (dimensions, colours per region, feature checklist, tolerances) before
  every asset, judged in the required views; measurement on the original through a matched
  camera; organic forms use component and self-overlap gates instead of mask tracing;
  builders use `--set` overrides instead of source rewrites; generated or imported meshes
  receive orientation checks.
- Retargeting reviews characters animated, including extreme poses and head, neck, shoulder,
  hip and inner-thigh close-ups, measures rigid-layer drift against a contract tolerance, and
  adds pitfalls for narrowed checks, bone rolls, shearing transition triangles, garment liners
  and held-prop reach.
- The visual reviewer describes the candidate before comparing, reports overshoot, and returns
  `unverified` when motion is in scope but only static renders were supplied. Live preview
  rounds shown to the user take the same review gate as a delivery under the chosen profile.

## 1.5.0 - 2026-10-01

### Added

- Added `agentkit update` to install `agent-manifesto-kit@latest` globally through npm,
  with streamed output, strict argument validation and propagated installation failures.
  Project capabilities continue to refresh through `agentkit sync`.

- Expanded `blender-3d` with a `blender-asset` entry skill and nested Quick, Standard and
  Production workflows. The full bundle syncs into Claude and Codex with no CLI changes.
- Added compact artifact/evidence handoffs, bounded repair reservations and per-phase usage
  records that distinguish unknown metrics from measured zero and identify parent/child calls.
- Added task-defined strict motion thresholds with coverage reporting, exact exported clip-set
  validation and optional mesh, skin and rig requirements.

### Changed

- Reference matching uses task-specific tolerances and identity checks instead of a universal
  silhouette score. Review effort and required views follow the chosen profile and changed scope.
- Retargeting chooses root displacement explicitly and applies pose offsets only to observed
  defects. Required missing evidence blocks acceptance; independent review is required for
  Production. Consumer projects retain machine paths, model choices and budgets.

### Fixed

- Package-content tests omit lifecycle scripts from their temporary manifests so npm 10
  cannot run Git hook setup outside a repository during `npm pack --dry-run`.
- Loop-seam checks sample fractional action endpoints precisely instead of rounding both to
  the same whole frame and potentially hiding a rotation discontinuity.

## 1.4.0 - 2026-10-01

### Added

- Added the public `session-retro` bundle: a digest-preparation skill and a read-only
  `retro-analyst` agent that reviews a finished Claude Code or Codex session and proposes at most
  five evidence-backed improvements (new or fixed scripts, skill pitfalls, project facts,
  removals). Approved changes use the consumer project's normal workflow. Its scripts summarize both tools' session logs
  (`session_digest.py`), provide one Stop hook for both tools that never blocks and nudges once
  per session when failure, repetition, inline-script, file-churn or correction thresholds are
  crossed (`retro_hook.py`), and register that hook in personal `.claude/settings.local.json`
  (or shared `.claude/settings.json` with `--shared`) and `.codex/hooks.json` (`install_hooks.py`).

### Changed

- Python bytecode caches are ignored so they cannot enter the repository or the package.

### Fixed

- `adopt` accepts `--provider=codex` as well as `--provider codex`. Missing option values,
  unknown adoption options and extra positional arguments fail before files are copied,
  instead of silently selecting the default Claude layout.
- Retro hook state stores derived pending-tool metadata without raw commands or request text,
  and resets counters when a transcript is truncated or replaced by a different path.
- Hook installation preserves unrelated scripts named `retro_hook.py` and rejects provider
  overrides among threshold flags. Digest detail is capped while signal totals remain exact.

## 1.3.0 - 2026-09-30

### Added

- Added `agentkit ingest <path>` to import a skill folder, a Claude agent `.md`, or a Codex
  agent `.toml` into `collection/` (flat or `--bundle <name>`) in canonical form. Codex agents
  become Markdown agents with a read-only `tools:` list for read-only sandboxes and a `codex:`
  block for other settings.
- Added `agentkit sync` to keep hard copies of skills and agents in a project's native Claude
  (`.claude/skills`, `.claude/agents`) and Codex (`.agents/skills`, `.codex/agents/*.toml`)
  locations, tracked by `.agentkit-lock.json`: owned files update in place, local edits and
  unowned files are kept unless `--force`, dropped items and providers are removed, and
  `--dry-run` previews changes.
- Added the public `blender-3d` bundle: `blender-reference-model` and `blender-mocap-retarget`
  skills with tested Blender and image scripts, and a read-only `visual-reviewer` agent.

### Changed

- Boolean CLI flags (`--force`, `--replace`, `--dry-run`) no longer consume a following
  positional argument.
- A read-only Claude tool list is reported as translated to Codex `sandbox_mode` rather than
  dropped.
- The `kit-adopt` bundle names `AGENTS.md` (or the tool's equivalent root contract) as the
  instruction entrypoint instead of listing a Claude-specific file.

## 1.2.1 - 2026-09-30

### Fixed

- Fixed Codex adoption so Codex can discover adopted capabilities: skills are now written to
  `.agents/skills/<name>/` instead of `.codex/skills/`, and agents are rendered as native Codex
  TOML (`.codex/agents/<name>.toml` with `name`, `description`, `developer_instructions`)
  instead of Markdown. Read-only Claude tool lists map to `sandbox_mode = "read-only"`; an
  optional `codex:` frontmatter block supplies other Codex settings; other Claude-only keys are
  dropped with a warning. `.claude/skills/` and `.claude/agents/*.md` references are rewritten
  to the matching Codex locations.
